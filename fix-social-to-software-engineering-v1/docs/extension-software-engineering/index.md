# Software Engineering

## What This Section Covers

Software engineering is about designing, building, testing, maintaining, and improving software systems in a structured way.

This section helps students understand software development as more than just writing code. Good software needs clear requirements, careful design, testing, documentation, teamwork, and long-term maintenance.

## Learning Goals

By the end of this section, students should be able to:

- explain what software engineering means
- describe the main stages of the software development life cycle
- understand the difference between programming and software engineering
- explain why testing and documentation are important
- understand why maintainability matters
- describe common software development roles and responsibilities
- connect software engineering ideas to real projects and the IA

## Key Topics

| Topic | What You Should Understand |
|---|---|
| Software engineering | A structured approach to developing software |
| Requirements | What the user or client needs the system to do |
| Design | Planning the structure, data, interface, and logic of the system |
| Implementation | Writing the actual program code |
| Testing | Checking that the program works correctly and meets requirements |
| Documentation | Explaining how the system works and how to use or maintain it |
| Maintenance | Fixing, updating, and improving software after release |
| Version control | Tracking changes to code and project files |
| Teamwork | Coordinating tasks, communication, and responsibilities |

## Why Software Engineering Matters

A program may work for one small task, but real software usually needs to be used, changed, tested, and maintained over time.

Good software engineering helps developers:

```text
reduce errors
understand user needs
build maintainable code
test systems properly
work better in teams
manage larger projects
improve software after release
```

## Programming vs Software Engineering

| Programming | Software Engineering |
|---|---|
| Focuses on writing code | Focuses on the whole software development process |
| Often solves one specific problem | Manages requirements, design, testing, deployment, and maintenance |
| Can be done by one person | Often involves teamwork and project management |
| Main output is code | Output includes code, documentation, tests, and design decisions |
