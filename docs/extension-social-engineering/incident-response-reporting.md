# Incident Response and Reporting

## 1. Lesson Goals

By the end of this lesson, students should be able to:

- explain why quick reporting matters
- identify steps after a suspicious message or account compromise
- distinguish containment, recovery, and review
- explain how to respond if a link was clicked or password was entered
- design a school-friendly reporting process
- write safe incident response advice

### English Explanation

When a suspicious event happens, the most important thing is not to stay silent because of fear or embarrassment. The earlier it is reported, the easier it is to reduce damage.

Common situations:

- suspicious email received but not clicked
- suspicious link clicked
- password entered
- verification code shared
- suspicious attachment opened
- unusual account login noticed

Response goals:

1. containment: limit damage
2. recovery: restore a safe state
3. review: learn and improve

Students should understand that reporting is not “admitting stupidity”. It protects the whole community.

## 5. Real-life Example

### Example: Student clicked a suspicious link

Safe response:

| Action | Reason |
|---|---|
| stop using the page | avoid entering more data |
| report to teacher/IT | support can check risk |
| change password if entered | reduce account takeover risk |
| sign out other sessions | remove attacker access |
| check recent activity | identify possible misuse |

---

## 6. Defensive Recognition Pattern

```text
Notice suspicious event
→ stop further action
→ preserve evidence if safe
→ report quickly
→ contain risk
→ recover account/device
→ review and improve
```

---

## 7. Scenario Analysis

### Scenario

A student entered their school password into a fake login page. They realize the link was not the official school domain.

| Risk | Response |
|---|---|
| password theft | change password immediately |
| attacker active session | sign out other sessions if possible |
| reused password | change same password elsewhere |
| school data risk | report to school IT |
| future attack | review warning signs |

---

## 8. Explanation of the Scenario

The most important action is quick reporting and containment. If the student waits, the attacker may use the password to access school systems, send more phishing messages, or copy data.

---

## 9. Step-by-step Defensive Response

| Step | Defensive Action |
|---|---|
| 1 | Stop interacting with suspicious page/file/message |
| 2 | Do not delete evidence immediately if reporting needs it |
| 3 | Report to teacher, IT, or official reporting channel |
| 4 | Change password if credentials were entered |
| 5 | Enable or reset MFA if needed |
| 6 | Sign out other sessions if possible |
| 7 | Check account activity |
| 8 | Review how the incident happened and update training |

---

## 10. Common Mistakes

| Mistake | Why it is a problem | Better habit |
|---|---|---|
| Hiding the incident | Delays response and increases damage | Report quickly |
| Deleting everything immediately | Evidence may be useful | Preserve safe evidence such as screenshot |
| Only changing password | Other sessions or reused passwords may remain risky | Also report and check activity |
| Blaming the person who reported | Discourages future reporting | Use supportive response |
| Continuing to click around | May worsen compromise | Stop and seek help |

## 11. Guided Practice

### Practice 1

Why should a clicked phishing link be reported quickly?

<details><summary>Suggested Answer</summary>

Quick reporting allows support staff to contain risk, block links, reset accounts, warn others, and reduce damage.

</details>

### Practice 2

What should a student do after entering a password on a fake site?

<details><summary>Suggested Answer</summary>

Stop using the site, report immediately, change the password, sign out other sessions if possible, and check for suspicious account activity.

</details>

## 13. Exam-style / Reflection Questions

### Question 1 [4 marks]

A user clicked a phishing link and entered their password. Describe what they should do.

<details><summary>Mark Scheme Style Answer</summary>

They should stop using the suspicious page and report the incident immediately to the correct support team. They should change the password, sign out other active sessions if possible, enable or reset MFA, check account activity, and change the same password on other services if it was reused.

</details>

### Question 2 [3 marks]

Explain why organizations should encourage quick reporting of social engineering incidents.

<details><summary>Mark Scheme Style Answer</summary>

Quick reporting allows the organization to contain the incident, block malicious links, reset compromised accounts, warn other users, and reduce damage. A no-blame culture makes users more likely to report quickly.

</details>
