# IA Overview

## 1. What the IA Is

The Computer Science IA is an individual project where a student develops a computational solution for a real client or user need.

A strong IA is not just code. It includes:

- clear problem analysis
- real client/user context
- justified design
- development evidence
- testing
- evaluation against success criteria
- reflection on limitations and improvements

## 2. What Makes a Good IA Topic

A good IA topic usually has:

| Feature | Explanation |
|---|---|
| Real user | Someone has a real need |
| Clear problem | The problem can be explained specifically |
| Suitable scope | Not too simple, not impossible |
| Computational solution | Requires programming/design |
| Testable success | Can be evaluated with criteria |
| Student ownership | Student understands and builds the solution |

## 3. Weak IA Topics

| Weak Topic | Problem |
|---|---|
| Generic calculator | Too simple and no real client need |
| Huge social media app | Too large |
| Copying an online tutorial | Low originality and understanding |
| Pure website with no logic | May not show enough CS thinking |
| Vague “help students study” app | Need specific user and requirements |

## 4. Better Topic Examples

| Better Topic | Why Better |
|---|---|
| Homework tracking system for a specific teacher | Real user and clear need |
| Library borrowing tracker for a small school club | Clear data and workflow |
| Revision quiz app for a specific class | Testable learning features |
| Inventory system for a small classroom store | Clear requirements and database logic |
| Timetable conflict checker | Algorithmic thinking |

## 5. IA Workflow

```text
Find client/user
→ investigate problem
→ define requirements
→ write success criteria
→ design solution
→ develop product
→ test with data
→ evaluate against criteria
→ reflect and improve
```

## 6. Student Habit

Keep evidence as you work:

- screenshots of development
- design diagrams
- test tables
- version notes
- client feedback
- problems and fixes

## 7. Quick Reflection Questions

1. Who is the client or target user?
2. What exact problem do they have?
3. Why is a computational solution suitable?
4. What data will the system store or process?
5. How will you prove the solution works?
