# Computational Solution Overview

## 1. What Is a Computational Solution?

A computational solution is a software-based solution created to solve a specific problem. It should use computer science ideas such as programming, data, algorithms, logic, testing, and evaluation.

For the IA, this means your product should not be a random app, a copied tutorial, a simple programming exercise, or a report about technology. It should be a designed solution to a clearly specified problem.

At SL, the public 2027 subject brief allocates **35 hours** to this computational solution and gives it a weighting of **30%**. Detailed submission packaging must still follow the latest official guidance provided by your school.

A strong computational solution usually has these qualities:

- there is a real or clearly defined problem
- the solution is created by the student
- the solution uses computational thinking
- the product can be tested
- the documentation explains the development process

## 2. What Makes It Computational?

| Feature | What it means in an IA project |
|---|---|
| Problem-solving | The project solves a clear problem, not just shows a random feature |
| Algorithmic thinking | The solution uses steps, rules, decisions, loops, or calculations |
| Data handling | The solution stores, searches, updates, validates, or processes data |
| Decomposition | The problem is split into smaller parts or modules |
| Testing | The product can be tested against success criteria |
| Evaluation | The final product can be judged against the original problem |

The exact balance depends on the project. A small project can still be strong if it has a clear problem, meaningful logic, useful data handling, and testing evidence.

## 3. Computational Solution vs Weak Project

| Strong computational solution | Weak project |
|---|---|
| Solves a clearly explained problem | Has no clear problem |
| Uses meaningful programming logic | Only displays static information |
| Stores or processes data where appropriate | Only stores temporary data in RAM with no meaningful persistence |
| Has measurable success criteria | Uses vague goals |
| Can be tested with different cases | Only works for one perfect input |
| Shows the student's own planning and development | Mainly follows a tutorial or template |

The goal is not to make the biggest possible product. The goal is to make a suitable product that solves a clear problem and gives you enough evidence to explain, test, and evaluate your work.

## 4. How the IA Process Connects to Criteria A-E

| IA process stage | Related criterion | What students should focus on |
|---|---|---|
| Understand the problem | Criterion A: Problem specification | Define the problem, context, and need for a computational solution |
| Plan the solution | Criterion B: Planning | Success criteria, resources, timeline, and plan |
| Explain the system | Criterion C: System overview | Structure, algorithms, data model, and testing strategy |
| Build the product | Criterion D: Development | Programming techniques and development evidence |
| Judge the product | Criterion E: Evaluation | Success criteria, limitations, and improvements |

Keep the official criterion names visible while you plan. This helps your project stay aligned with the IA structure instead of becoming a general programming portfolio.

## 5. Example: Library Borrowing System

A small library needs a system to track books, borrowers, and whether each book is currently borrowed or returned.

- Problem: staff currently use paper notes, so it is easy to lose track of which books are available.
- Possible users: a librarian, library assistant, or student helper.
- Main features: add books, add borrowers, record borrowing, record returns, search for books, and view overdue items.
- Data needed: book title, book ID, borrower name, borrower ID, borrow date, return date, and status.
- Why this can be computational: the system stores data, searches records, updates status, validates inputs, and applies rules such as checking whether a book is already borrowed.
- What could make it too simple: only showing a static list of books or storing data only until the program closes.
- What could make it stronger: persistent storage, search/filter tools, validation, overdue detection, clear success criteria, and tests using normal and invalid cases.

## 6. Example: Study Planner

A student wants to plan revision tasks before exams and track whether each task has been completed.

- Problem: revision tasks are spread across notebooks, messages, and memory, so important tasks are missed.
- Main features: add tasks, set subject and deadline, mark tasks complete, filter by subject, and show upcoming tasks.
- Data needed: task name, subject, deadline, priority, completion status, and optional notes.
- Possible algorithms or logic: sorting tasks by deadline, filtering by subject, calculating days remaining, and warning when a task is overdue.
- Testing possibilities: test valid deadlines, missing task names, completed tasks, overdue tasks, and filtering with no matching results.

This project should stay focused. It becomes too large if it tries to become a full school management platform, social app, calendar system, and notification service all at once.

## 7. Signs Your Idea Is Too Simple

- It only has one calculation.
- It only displays fixed text or images.
- It has no meaningful input, processing, or output.
- It has no data storage or data processing.
- It cannot be tested beyond "it opens".
- It is mostly copied from a tutorial.
- It does not solve a clear problem.

## 8. Signs Your Idea Is Too Large

- It needs too many advanced features.
- It needs online payment, live multiplayer, or complex deployment.
- It depends on external APIs that may fail or require permissions.
- It needs too much data collection.
- It cannot be finished within the available time.
- It is a game or app idea where most features cannot realistically be completed.

## 9. Practical Checklist Before You Start

- [ ] I can explain the problem in one paragraph.
- [ ] I can explain who the user is.
- [ ] I can list the main features.
- [ ] I can write measurable success criteria.
- [ ] I can identify what data the system needs.
- [ ] I can test the product with normal and invalid cases.
- [ ] I can build a working version with my current or learnable programming skills.
- [ ] I can explain how my solution uses computational thinking.
- [ ] I can complete it without copying an existing project.
