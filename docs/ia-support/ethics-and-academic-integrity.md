# Ethics and Academic Integrity

## 1. Why Ethics Matters in the IA

The IA is not only about building software. You also need to think about how your software affects people, data, privacy, fairness, and trust.

A project can be technically impressive but still ethically unsuitable. You should think about ethics before collecting data, recording feedback, building sensitive features, or publishing evidence in your documentation or video.

Academic integrity is also part of the IA process. The final product and documentation must represent your own work, and any external help or sources should be acknowledged where required.

## 2. Key Ethical Responsibilities

| Responsibility | What it means in an IA project | Example |
|---|---|---|
| Consent | People involved should know what data or feedback is being collected and why | Asking a user before recording interview feedback |
| Data privacy | Personal data should be protected and only used for the project purpose | Not publishing real names, phone numbers, or private records |
| Secure storage | Collected data should be stored safely | Keeping files private and not sharing raw personal data online |
| Ethical purpose | The software should not harm, spy on, deceive, or unfairly target people | Avoiding tools designed to monitor people without permission |
| Own work | The final product and documentation must represent the student's own work | Not submitting copied code as original work |
| Source acknowledgement | External ideas, libraries, tutorials, data, images, and AI help should be acknowledged where required | Citing a library or tutorial used to learn a technique |

## 3. Consent

Consent means people understand what they are being asked to do and agree before they take part.

You may need consent when:

- interviewing a user or client
- collecting feedback
- collecting real data
- recording video or screenshots involving people
- using someone's organisation, workflow, or data
- using user testing results

Consent checklist:

- [ ] I have explained the purpose of my project.
- [ ] I have explained what information I am collecting.
- [ ] I have explained how the information will be used.
- [ ] I have avoided collecting unnecessary personal data.
- [ ] I have permission before using someone's feedback, images, or data.
- [ ] I have followed my school's consent procedure.

Do not secretly collect data or record people.

## 4. Data Privacy and Secure Storage

You should collect the minimum data needed for the project. If real data is not necessary, mock data is usually safer.

| Risk | Why it matters | Safer approach |
|---|---|---|
| Collecting real names | Personal data may be exposed | Use fake names or IDs if possible |
| Storing phone numbers or addresses | Sensitive data risk | Avoid collecting unless truly necessary |
| Uploading raw data to a public repo | Anyone may access it | Keep data private or use mock data |
| Showing private records in screenshots | Privacy breach | Blur, anonymise, or use mock data |
| Sharing database files online | Could expose user information | Use sample data instead |

## 5. Mock Data

Mock data is fake but realistic sample data used for testing and demonstration. It is often safer than real personal data.

| Real data risk | Mock data alternative |
|---|---|
| Real student names | Student001, Student002 |
| Real library borrowers | Borrower A, Borrower B |
| Real medical or personal records | Sample records with fictional values |
| Real phone numbers | 000-0000 or clearly fake examples |
| Real addresses | Fictional locations |

Mock data should still be realistic enough to test the system properly. For example, a borrowing system should have enough sample records to test searching, borrowing, returning, duplicate IDs, and missing fields.

## 6. Ethical Project Purpose

Avoid projects that harm people, violate privacy, encourage cheating, bypass security, or collect data without permission.

| Risky project direction | Why it is problematic | Safer alternative |
|---|---|---|
| Tool to monitor classmates without permission | Privacy and consent issue | Personal study tracker using the student's own data |
| Tool to guess or steal passwords | Security and harm issue | Password strength checker that does not store passwords |
| Tool to scrape private data | Data privacy issue | Use public, permitted, or mock data |
| Exam cheating helper | Academic integrity issue | Revision quiz or flashcard system |
| Face recognition attendance system using real students | Sensitive biometric/privacy issue | Manual attendance tracker with mock data |

## 7. Academic Integrity

Academic integrity means your work is honest, original, and properly acknowledges help and sources.

You must avoid:

- copying another student's work
- copying a GitHub project and changing only small details
- submitting tutorial code as if it were fully original
- allowing another person to build the product
- hiding major AI-generated code or writing
- using uncited images, data, text, or code
- reusing the same work for another assessment if not allowed

| Situation | Acceptable if... | Risky if... |
|---|---|---|
| Using a tutorial | You use it to learn and then build your own adapted solution with citation | You copy the tutorial project and submit it as your own |
| Using an external library | You acknowledge it and can explain how it supports your project | You rely on it without understanding or citation |
| Asking a friend for help | They explain a concept and you write your own code | They write major parts of your code |
| Using AI | You follow school guidance, use it responsibly, and acknowledge it where required | You submit AI-generated work you cannot explain |
| Using online code snippets | You cite and adapt small parts responsibly | Your main product is copied from online code |

## 8. External Libraries and Sources

External libraries are allowed in many projects, but you should acknowledge them and understand their purpose.

Examples of sources to acknowledge:

- programming libraries
- tutorials
- documentation
- code snippets
- datasets
- images and icons
- AI tools
- advice from other people
- templates or frameworks

Acknowledgement table template:

| Source / tool | How it was used | What I changed or created myself | How I acknowledged it |
|---|---|---|---|
|  |  |  |  |

Follow your school's citation style and IB guidance.

## 9. AI Use

AI tools may be useful for learning, debugging, brainstorming, or improving explanations, but the final work must remain your own. You must follow your school's AI policy.

Responsible uses may include:

- asking for explanation of an error message
- asking for examples of a programming concept
- brainstorming possible project risks
- checking grammar of documentation
- generating alternative pseudocode to compare with your own understanding

Risky uses include:

- generating the whole product
- generating documentation and submitting without understanding
- hiding AI involvement
- using code that you cannot explain
- using AI to fake testing or feedback

AI use checklist:

- [ ] I can explain every major part of my code.
- [ ] I have not used AI to replace my own thinking.
- [ ] I have followed school guidance for acknowledging AI.
- [ ] I have checked AI suggestions for correctness.
- [ ] I have not included generated code that I do not understand.
- [ ] My final product reflects my own design and decisions.

## 10. What to Include in the IA Documentation

You do not need to write a long ethics essay, but you should include ethical and academic integrity details where relevant.

Possible places:

- Criterion A: mention user/context, consent, data sensitivity
- Criterion B: plan for mock data, privacy, resources, and citations
- Criterion C: data model should avoid unnecessary sensitive fields
- Criterion D: acknowledge libraries, external help, AI use, and testing data
- Criterion E: evaluate limitations, privacy, and responsible improvements
- Appendix: full source code and source acknowledgements where required

## 11. Common Mistakes

| Mistake | Why it is a problem | Better approach |
|---|---|---|
| Collecting real personal data when mock data is enough | Creates unnecessary privacy risk | Use fictional sample data |
| Not asking permission from user/client | Consent issue | Ask before collecting feedback or data |
| Copying a tutorial project | Academic integrity issue | Use tutorials only to learn techniques |
| Not citing a library | Source acknowledgement issue | List the library and its purpose |
| Using AI-generated code without understanding | Student ownership issue | Only use code you can explain and adapt |
| Uploading private data to GitHub | Public exposure risk | Keep real data private or use mock data |
| Building a harmful tool | Ethical issue | Choose a project that helps users safely |

## 12. Ethics and Academic Integrity Checklist

- [ ] My project has an ethical purpose.
- [ ] I have considered whether consent is needed.
- [ ] I have avoided collecting unnecessary personal data.
- [ ] I use mock data where real data is not needed.
- [ ] Any real data is stored securely.
- [ ] I do not publish private data in screenshots, videos, code repositories, or documentation.
- [ ] I have acknowledged external libraries and sources.
- [ ] I have followed school guidance on AI use.
- [ ] I can explain all important code and design decisions.
- [ ] The final product and documentation are my own work.
- [ ] I have not copied an existing project and presented it as my own.
- [ ] I have included citations or acknowledgements where required.

## 13. Quick Check

1. What does consent mean in an IA project?

<details>
<summary>Answer</summary>

Consent means people understand what information, feedback, or data is being collected, why it is being collected, and how it will be used before they agree to take part.

</details>

2. Why is mock data often safer than real data?

<details>
<summary>Answer</summary>

Mock data avoids exposing real personal information while still allowing the product to be tested with realistic sample records.

</details>

3. Why is copying a tutorial project risky?

<details>
<summary>Answer</summary>

It may not show your own problem choice, design, programming decisions, or understanding. A tutorial can help you learn, but the submitted product must be your own adapted work.

</details>

4. Why should external libraries be acknowledged?

<details>
<summary>Answer</summary>

Acknowledging libraries makes it clear which tools helped your project and which parts you created yourself. It also supports academic integrity.

</details>

5. Why must students be careful with AI-generated code?

<details>
<summary>Answer</summary>

AI-generated code may be incorrect, unsuitable, or hard to explain. If you use code you do not understand, the work may no longer show your own programming skill.

</details>

6. What is one example of an ethically risky IA idea?

<details>
<summary>Answer</summary>

One example is a tool that monitors classmates without permission. It raises privacy and consent concerns. A safer alternative would be a personal study tracker using your own data.

</details>
