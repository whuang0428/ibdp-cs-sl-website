# IA Support

::: tip Internal Assessment Support
This section supports students with the computational solution process. It should guide planning, development, testing, and evaluation.
:::

## Section Overview

The IA requires students to develop a computational solution for a real client or user. This section should help students manage the project step by step.

## IA Workflow

| Stage | Focus |
|---|---|
| Problem Identification | Understand the client and problem |
| Requirements | Define what the solution must do |
| Success Criteria | Decide how the solution will be judged |
| Design | Plan data, interface, algorithms, and structure |
| Development | Build the solution |
| Testing | Check the solution with test data |
| Evaluation | Reflect against success criteria |
| Documentation | Present the process clearly |

## Good IA Project Features

A strong project usually has:

- a clear real user
- a specific problem
- realistic scope
- measurable success criteria
- evidence of planning
- useful testing
- clear explanation of decisions
- reflection based on user feedback

## Common Mistakes

| Mistake | How to Avoid It |
|---|---|
| Choosing a project that is too large | Keep the scope realistic |
| No real client | Find a real person with real needs |
| Vague success criteria | Make criteria measurable |
| Weak testing | Use normal, boundary, and invalid data |
| Only describing code | Explain decisions and link them to the problem |

## Quick Check

1. Why is a real client important?
2. What makes a success criterion measurable?
3. Why should testing include invalid data?
4. What is the purpose of a development log?
5. How should evaluation link back to success criteria?
